Graph systems 27k lines · 381 tests · MIT

Blast Radius

When an npm package is compromised, defenders have minutes to answer one question: who is actually exposed, right now?

A transitive reverse-dependency closure is not a similarity problem — it is a graph traversal, five hops deep, over tens of millions of versioned nodes. So the graph is stored twice: a collapsed Package→Package layer so traversal stays flat as depth grows, and a version-precise Release→Package layer underneath so the forensic questions stay answerable.

  • Reduced supply-chain analysis to three operations: traversal, semver resolution, OSV correlation
  • Live osv.dev lookups — no crawl coverage required
  • Deployed monitoring and API surfaces with signed webhooks

Agent safety 347 tests · zero write-tools

Airlock

Nothing reaches production without passing through the airlock.

A change-control console where every irreversible production change is proven on a shadow copy before a human is ever asked to approve it. Proposals execute against a shadow database, checksums are verified, rollback is prepared — and approval is withheld until the proof passes.

  • 347 documented passing tests; zero production-write tools exposed to agents
  • Policy gates plus tamper-evident ledgers on every proposal
  • CodeQL in CI and an MCP tool layer for agent integration

Semantic Output Cache

Exact-match caches never hit on LLM traffic — nobody phrases it the same way twice. This one embeds each output and serves it when cosine similarity clears a threshold, combining embeddings with SHA-256 identity so cache-hit coverage extends well past literal text matches. Only key hashes are stored; JS and Python SDKs, threat model in the repo.

How I build

Four rules I hold every project to. They are unglamorous, and they are where most of the real decisions end up.

01

No mocked data. Anywhere.

Every number on every screen comes back from a query that was actually run — including empty states. A demo that lies is worse than no demo.

02

Measured, not claimed.

Every panel in Blast Radius carries the latency of the query that produced it. If I say it is fast, there is a number next to the claim.

03

Secrets are a design problem.

Not a checklist item. The .gitignore is a deliberate glob, because the explicit list already failed once — and that is the failure mode the pattern exists to prevent.

04

Commits explain the change.

Not the diff. Answer the lockfile question from the lockfile. You can read the history and know what happened.
